# P1.3 — JWT Bearer, CORS, exception handler và base response

## 1. Trạng thái và quyết định mới

Người dùng xác nhận BPM là web hoàn chỉnh, tự phát JWT và dùng Bearer token.
C-18 làm rõ lựa chọn authentication trong đặc tả: security stateless, không lưu authentication
vào HttpSession, không nhận token qua cookie/query/form. Backend dùng Spring
Security Resource Server và Nimbus JWT có sẵn trong hệ sinh thái Spring.

Đã triển khai service phát JWT HS256, encoder/decoder và HTTP security. Chưa có
API login/refresh hoặc bảng tài khoản: chúng được nối ở P2.1. Không mở endpoint
cho client tự gửi userId/permissions để xin token.

**Chưa chạy build/test.** Có test source sử dụng token ký thật để bạn tự chạy.
Code helper/mapper/policy/use case/controller P1.3 đã được hoàn thiện ngày
02/11/2026, chờ người dùng chạy kiểm tra. Adapter runtime còn chờ schema/P2/P4;
P2.1 chưa hoàn thành.

## 3. Cấu hình JWT mặc định trong dev

.env.example đã có:

```dotenv
JWT_SECRET_KEY=dev-only-bpm-jwt-secret-change-before-deploy-2026
JWT_ISSUER=https://bpm.local
JWT_AUDIENCE=bpm-api
JWT_ACCESS_TOKEN_TTL=30m
CORS_ALLOWED_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
```

Theo yêu cầu của bạn, profile dev/Compose dev có sẵn secret mặc định công khai để
chạy thử. Bạn thay JWT_SECRET_KEY trong .env; không commit secret thật. HS256 yêu
cầu key ít nhất 32 byte UTF-8. Chọn key ngẫu nhiên đủ entropy khi triển khai thật.

Profile chung không có secret mặc định; ngoài dev/test phải cấp JWT_SECRET_KEY.
Đổi secret làm token đã ký bằng key cũ không còn hợp lệ. Issuer là định danh của
BPM, không phải URL mà decoder phải gọi để tìm khóa; không cần dịch vụ xác thực
bên ngoài hoặc SSO cho cấu hình này.

TTL mặc định 30 phút là **thời gian sống từ lúc phát token**. Nó không phải idle
timeout và không được kéo dài khi người dùng thao tác. Đây là baseline kỹ thuật
cấu hình được, thay cho timeout session cũ. Decoder chấp nhận lệch đồng hồ 30 giây.

## 4. Phát token và kiểm tra token

Từ P2.1c, `NimbusAccessTokenIssuer.issue(userId, loginGrantId, securityVersion,
permissions)` tạo:

| Claim | Ý nghĩa |
| --- | --- |
| iss | JWT_ISSUER |
| aud | Chứa JWT_AUDIENCE |
| sub | ID ứng dụng của tài khoản đã xác thực |
| iat | Thời điểm phát từ Clock UTC |
| nbf | Token có hiệu lực từ thời điểm phát |
| exp | iat + JWT_ACCESS_TOKEN_TTL |
| jti | UUID mới cho mỗi token |
| sid | ID login grant do server tạo |
| ver | Security version hiện tại của tài khoản |
| permissions | Mảng quyền lấy từ nguồn server tin cậy, có thể rỗng |

Header cố định alg=HS256, typ=JWT. Decoder chỉ nhận HS256, kiểm tra chữ ký bằng
secret, issuer, audience, exp/nbf, sub/iat/jti/sid/ver và cấu trúc permissions. Không tin
claims trước khi kiểm tra chữ ký. Token thiếu exp hoặc có exp <= iat bị từ chối.
Snapshot permissions trong JWT không được dùng để cấp quyền; converter P2.1c
đọc quyền hiện tại từ DB và chuyển thành GrantedAuthority nguyên tên.

Login use case P2.1c inject `AccessTokenIssuer` và thực hiện:

1. Kiểm tra username/password bằng account store và PasswordEncoder.
2. Kiểm tra ACTIVE, mật khẩu tạm và chính sách tài khoản.
3. Đọc ID/quyền từ server.
4. Tạo login grant/refresh credential hash, rồi gọi issuer với userId/sid/ver/quyền.
5. Trả DTO qua ApiResponseFactory, với Cache-Control no-store.

Không lấy userId/permissions từ request login để ký lại nguyên xi. Không thêm
endpoint generate-token public. P2.1c chỉ mở `POST /api/v1/auth/login`;
refresh/logout được mở khi có implementation P2.1d.

IssuedAccessToken có hình dạng:

```json
{
  "accessToken": "<signed-jwt>",
  "tokenType": "Bearer",
  "expiresAt": "2026-11-01T03:30:00Z",
  "expiresIn": 1800
}
```

Token chỉ xuất hiện trong response xác thực được chủ động cho phép. Không log
token/secret/password hoặc trả chúng trong API danh sách, lỗi, audit.

## 5. HTTP security và CORS

| Request | Quy tắc |
| --- | --- |
| GET /actuator/health và health subpath | Public để Docker healthcheck hoạt động |
| /api/v1/** | JWT Bearer hợp lệ; use case/policy vẫn kiểm tra quyền tài nguyên |
| Đường khác | Deny by default |
| Servlet ERROR dispatch | Cho phép JSON fallback xử lý |
| Authorization thiếu/sai/hết hạn | 401 JSON + WWW-Authenticate: Bearer |
| Có JWT hợp lệ nhưng thiếu quyền | 403 JSON |
| Preflight đúng origin/method/header | Xử lý trước authentication |

JWT được gửi duy nhất qua Authorization header. Security không dùng HttpSession
để lưu/đọc authentication, không tạo JSESSIONID cho request API. Token ở query
access_token, form hoặc cookie không cấp quyền. Form login, HTTP Basic, session
logout và CSRF đã tắt cho cơ chế Bearer-header này.

CORS chấp nhận Authorization, Content-Type, Accept, X-Correlation-ID và
Idempotency-Key. Expose X-Correlation-ID, Location, WWW-Authenticate.
allowCredentials=false; frontend không cần gửi cookie phiên. Origin dev mặc định:
http://localhost:5173 và http://127.0.0.1:5173. Đổi CORS_ALLOWED_ORIGINS nếu frontend
dùng địa chỉ khác.

Lỗi CORS bị processor chặn trước MVC có thể dùng response mặc định của Spring
CORS. Origin bị từ chối không được browser cho đọc response. Chưa thêm cookie
refresh token; nếu sau này đưa authentication vào cookie, cần đánh giá CSRF lại.

Frontend gọi API:

```javascript
await fetch(`${apiBase}/api/v1/some-resource`, {
  method: "POST",
  credentials: "omit",
  headers: {
    "Content-Type": "application/json",
    Authorization: `Bearer ${accessToken}`
  },
  body: JSON.stringify(payload)
});
```

some-resource là ví dụ, chưa có route nghiệp vụ tương ứng.

## 6. Response và global handler

ApiResponse dùng các trường timestamp, status, code, message, correlationId, data,
details. Thành công: code=OK, details=[]; lỗi: data=null và status đúng HTTP status
thật. Không bọc response tự động bằng ResponseBodyAdvice.

Controller inject ApiResponseFactory rồi gọi responses.success(dto, request).
Với 201, trả ResponseEntity.status(CREATED) đồng thời truyền CREATED vào factory.
Payload danh sách nằm trong data; PageResult.totalPages đã được hoàn thiện và có
test source cho trường hợp biên lớn. Download và 204/205 không dùng JSON body
factory. Actuator giữ hợp đồng health riêng.

| Lỗi | HTTP |
| --- | --- |
| JSON hỏng, sai kiểu request | 400 |
| Bearer thiếu/không hợp lệ/hết hạn | 401 |
| Thiếu quyền | 403 |
| Không tìm thấy | 404 |
| Method/Accept/content type sai | Giữ 405/406/415 và headers framework |
| Input Bean Validation MVC | 422, có details field |
| Revision/optimistic lock | 409 |
| Lỗi bất ngờ/validation đầu ra | 500, message chung |

ApplicationException chỉ dùng message an toàn chủ động viết. Không trả stack trace,
exception SQL/engine hoặc rejected value. Log kỹ thuật có correlation ID và không
ghi Authorization, body, password, secret hoặc token.

## 7. Refresh, logout và khóa tài khoản

JWT tự chứa thông tin không tự mất hiệu lực khi frontend xóa token. Hiện chỉ có
access token, chưa có refresh token hoặc cơ chế thu hồi sau logout. Logout phía
server không được giả lập bằng xóa session; endpoint cũ đã bỏ.

P2.1 cần hoàn thiện login/refresh/logout và thu hồi phù hợp. Khi khóa tài khoản,
quyền đã đổi hoặc logout cần có hiệu lực với token đã phát, phải kiểm tra trạng
thái/token version hoặc cơ chế revoke ở server. Việc chỉ verify chữ ký/exp chưa
đáp ứng yêu cầu đó. Không đổi yêu cầu tài khoản ACTIVE thành tin claim active=true.

SpringSecurityCurrentActorProvider còn TODO để nối sub với tài khoản/trạng thái/
quyền hiện tại từ DB. JWT hợp lệ là bước authentication, không thay policy quyền
theo từng hồ sơ/task hoặc trạng thái hiện tại của tài khoản.

```powershell
Invoke-RestMethod http://localhost:8080/actuator/health
```

Mong đợi healthy/UP. Compose dev có secret mặc định nên không cần tạo key lần đầu.
P2.1c đã bổ sung login API và `/me`. Code/cấu hình/test bootstrap tài khoản
dev đã bị xóa hoàn toàn; cần tài khoản được tạo theo luồng quản trị P2.2
hoặc fixture test để xin token.
ApiFoundationWebTests vẫn gọi service phát token trực tiếp để cô lập việc kiểm tra
Bearer filter/decoder thật.

```powershell
docker compose -p bpm-test -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from tests
$testExitCode = $LASTEXITCODE
New-Item -ItemType Directory -Force target | Out-Null
docker compose -p bpm-test -f compose.test.yaml cp tests:/workspace/target/surefire-reports ./target/test-results
docker compose -p bpm-test -f compose.test.yaml down
$testExitCode
```

Mong đợi exit code 0. Các ca có source: token do service phát cho phép POST không
CSRF, không tạo session; session cũ/query token không cấp quyền; sai chữ ký,
issuer, audience, exp/nbf/claims trả 401; permission thiếu trả 403; lỗi MVC,
correlation/MDC và CORS giữ đúng hợp đồng. Không mock JwtDecoder để kết luận kiểm
tra chữ ký thành công. Smoke test PostgreSQL/Flowable cũ vẫn giữ.

**Các lệnh/test trên chưa được agent chạy.** Phần còn TODO của P1.3 do bạn tiếp
