## Sửa lỗi khởi tạo security trong MVC test

`ApiFoundationWebTests` dùng `@WebMvcTest` và import `SecurityConfiguration` thật.
Trong Spring Boot 4.1.2, auto-configuration security cho MockMvc nằm trong module
`spring-boot-security-test`. Dependency `org.springframework.security:spring-security-test`
đơn lẻ cung cấp test helpers nhưng không đưa module Boot này vào test classpath,
nên slice không có cấu hình tạo `HttpSecurity` khi tạo `securityFilterChain`.

Đã thay dependency bằng `org.springframework.boot:spring-boot-starter-security-test`
với scope `test`, dùng version do parent quản lý. Starter kéo cả module Boot và
`spring-security-test`; không đổi cấu hình JWT hoặc tắt security filter trong test.
Đã đối chiếu POM và metadata imports trong source JAR Boot 4.1.2 có sẵn trên máy;
người dùng đã xác nhận chạy lại test thành công sau bản sửa này.

Chạy lại lệnh Compose test bên dưới với `--build` để dùng `pom.xml` mới. Kỳ vọng
MVC context tạo được `HttpSecurity`; các ca JWT/CORS/401/403 đã có tiếp tục chạy
qua security thật. Người dùng đã xác nhận test và build/kiểm tra dev thành công.

## P1.4 — schema và test harness

- Giữ JPA `update` / Flowable auto-update ở dev; test dùng JPA `create-drop` và
  Flowable auto-update. Không thêm migration hoặc bảng nghiệp vụ giả.
- `@IsolatedPostgresTest` là annotation chung cho integration test có DB. Guard
  chạy trước khởi tạo schema, yêu cầu chỉ profile `test`, URL dạng
  `jdbc:postgresql://<host>:<port>/bpm_test`, user `bpm_test`; không cho URL query
  parameters. Guard của DataSource xác nhận lại PostgreSQL, catalog và user thật
  trước khi JPA/Flowable nhận DataSource.
- Entity `SchemaProbe` và seed SQL chỉ ở test classpath. Test xác nhận Hibernate
  tạo bảng từ DB trống và đọc seed bằng JPA; transaction test rollback seed.
  Không đóng fixture vào JAR runtime hoặc tạo tài khoản dev mặc định.
- Compose test không mở cổng DB, không dùng volume dev; DB nằm trên tmpfs. Các
  fixture BPMN được deploy chủ động trong từng test, không auto-deploy ở startup.
- Cấu hình chung bật history `audit` và tắt auto-deploy BPMN từ classpath; profile
  test tắt async executor để các fixture đồng bộ không có worker chạy nền.
- Workflow `.github/workflows/backend.yml` compile/test trên PostgreSQL Docker,
  thu báo cáo/log trước dọn stack, rồi package image runtime khi test đạt. Cần
  repository chạy trên GitHub Actions để workflow này tự thực thi.

### Chạy test từ DB trống, lặp lại hai lần

Trong PowerShell tại thư mục repository:

```powershell
docker compose -p bpm-test -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from tests
$testExitCode = $LASTEXITCODE
New-Item -ItemType Directory -Force target | Out-Null
docker compose -p bpm-test -f compose.test.yaml cp tests:/workspace/target/surefire-reports ./target/test-results
docker compose -p bpm-test -f compose.test.yaml down
Write-Output "Test exit code: $testExitCode"
```

Thu báo cáo trước `down`. Nếu Maven lỗi trước Surefire thì có thể chưa có báo cáo;
đọc log service `tests` trước khi dọn. Lặp lại toàn bộ khối để xác nhận DB tạm được
dựng lại và seed không trùng. Không chạy hai test runner đồng thời trên cùng DB.
Lệnh không ghép `compose.test.yaml` với Compose dev. Không dùng `down --volumes`
với project dev.

Kỳ vọng: cả hai lần exit code `0`, smoke test dùng PostgreSQL/catalog `bpm_test`,
`SchemaInitializationTest` đọc đúng seed, dữ liệu dev giữ nguyên. Test profile
chỉ nằm trong test resources; nếu chạy IDE phải cấp đủ `TEST_DATABASE_*` và dùng
DB/user `bpm_test` riêng.

## P1.5 — quy trình tối thiểu qua adapter

### Các file chính và ranh giới

| Vị trí | Trách nhiệm |
| --- | --- |
| `process/application/engine/ProcessEnginePort` và các record cùng package | Hợp đồng deploy/start/query/history, kết quả chứa ID và dữ liệu Java thuần. |
| `process/adapter/flowable/FlowableProcessEngineAdapter` | Gọi RepositoryService, RuntimeService và HistoryService; start theo definition ID. |
| `task/application/engine/TaskEnginePort`, `EngineTask` | Hợp đồng query task theo instance/assignee/candidate, claim và complete. |
| `task/adapter/flowable/FlowableTaskEngineAdapter` | Map task/identity links; claim đúng candidate và complete đúng assignee. |
| `shared/adapter/flowable/FlowableCalls` | Đổi lỗi engine thành mã lỗi ứng dụng với thông báo an toàn. |
| `shared/application/EngineInput` | Kiểm tra đầu vào kỹ thuật; chỉ nhận biến scalar, không persist Java/engine object tùy ý. |
| `src/test/resources/fixtures/p15-*.bpmn20.xml` | Hai fixture cùng cấu trúc Start → User Task → XOR → End; khác direct assignment và candidate queue. |
| `FlowableEngineIntegrationTest` | Chỉ điều khiển kịch bản qua application port; RepositoryService chỉ dùng để dọn đúng deployment của từng test. |

Không bật API process/task hoặc controller danh mục ở bước này. Adapter là bean
nội bộ; RBAC, ACTIVE check, self-approval, scope và resolve assignment vẫn cần
use case/policy P2/Phase 5 trước khi đưa vào luồng người dùng thật.

### Luồng ID và dữ liệu

```text
BPMN XML → deploy → deploymentId + definitionId/key/version
application record ID giả lập → businessKey
definitionId đã chọn + businessKey + variables → start → instanceId
instanceId → active task → taskId → claim nếu queue → complete(outcome)
instanceId → history với businessKey, definitionId, endActivityId và lịch sử task
```

`businessKey` trong test là `p15-record-<UUID>`, đại diện ID hồ sơ ứng dụng. Chưa
có bảng hồ sơ/catalog/version nên chưa lưu mapping bền vững giữa các bảng ứng dụng
và engine; phần đó nối khi có schema. Engine definition version không thay cho
revision ứng dụng. Business key chưa được bảo đảm unique/idempotent; test dùng ID
riêng và query trả danh sách. Start luôn dùng definition ID, không lấy latest by key.

Các biến P1.5 hỗ trợ String, Boolean, Integer, Long, Double, BigDecimal, giá trị
không null; map rỗng hợp lệ. Cấu trúc JSON lồng nhau và field binding để dành khi
thiết kế binding/form. Fixture direct dùng `reviewerId`; queue dùng
`candidateUserId` và `candidateGroupId`; complete gửi `outcome=APPROVE|REJECT`.

Group IDs truyền vào query/claim phải lấy từ danh tính tin cậy ở use case tương
lai. Adapter so sánh identity link candidate user/group, không dùng bảng Flowable
IDM để suy ra membership ứng dụng. Candidate task phải chưa claim; sau claim task
chuyển sang kết quả assignee. Không cho complete task chưa claim hoặc khác assignee.
Các truy vấn port hiện giới hạn theo instance/business key, chưa phải API inbox toàn hệ thống.

### Kịch bản test — người dùng đã xác nhận chạy thành công

| Kịch bản | Kết quả mong đợi |
| --- | --- |
| Direct assignee APPROVE / REJECT | Task thuộc reviewer; lần lượt kết thúc tại `approvedEnd` / `rejectedEnd`. |
| Candidate group APPROVE / REJECT | Task chưa có assignee; thành viên nhóm nhìn thấy queue, claim rồi complete. |
| Candidate user không thuộc nhóm | Candidate được chỉ định trực tiếp vẫn query/claim được. |
| Outsider claim, candidate complete trước claim, sai assignee complete | FORBIDDEN; task vẫn ở trạng thái trước thao tác. |
| Claim task đã có assignee | TASK_CONFLICT. Đây là kiểm tra tuần tự, chưa phải concurrency test. |
| Deploy version mới cùng key, start bằng ID cũ | Instance/task/history vẫn gắn definition ID được chọn. |
| Hai instance cùng assignee | Query theo instance/business key không trả task/instance của hồ sơ còn lại. |
| Instance/history không tồn tại | Optional rỗng; task không tồn tại hoặc definition ID sai trả NOT_FOUND. |
| Truyền process key thay definition ID | NOT_FOUND, không tự start latest. |
| Truyền Java object làm biến | INVALID_REQUEST, không tạo instance. |
| Kết thúc quy trình | Không còn runtime instance/task; history giữ IDs, business key, assignee, completedBy, timestamps và end activity đúng nhánh. |
| Complete lại task đã xong | NOT_FOUND, không chuyển bước lần hai trong thao tác tuần tự. |

Chạy toàn bộ bằng khối Compose ở P1.4; Maven `test` tự tìm các lớp `*Test`/`*Tests`,
không cần lệnh integration-test riêng. Các adapter mutation có transaction ở biên
adapter; test không bọc cả kịch bản trong transaction tự rollback. Test deploy
fixture chủ động và dọn deployment theo ID sau mỗi kịch bản. History được kiểm tra
trước khi dọn; muốn quan sát lỗi thì lấy báo cáo/log trước khi `down`.

Chưa chứng minh JPA + engine cùng rollback, claim/complete cạnh tranh hoặc restart;
