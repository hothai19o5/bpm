## 2. Transaction và concurrency — chạy bộ test thông thường

Trong PowerShell tại thư mục repository:

```powershell
docker compose -p bpm-test -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from tests
$testExitCode = $LASTEXITCODE
New-Item -ItemType Directory -Force target/test-results-p16 | Out-Null
docker compose -p bpm-test -f compose.test.yaml logs --no-color | Out-File -Encoding utf8 target/test-results-p16/compose.log
docker compose -p bpm-test -f compose.test.yaml cp tests:/workspace/target/surefire-reports ./target/test-results-p16
docker compose -p bpm-test -f compose.test.yaml down
Write-Output "Test exit code: $testExitCode"
```

Thu báo cáo trước khi `down`. Nếu Maven lỗi trước Surefire thì xem compose.log;
có thể chưa có thư mục báo cáo. Không chạy nhiều test runner trên cùng database.

Kỳ vọng: exit code `0`, các test cũ vẫn đạt, lớp
`FlowableTransactionConcurrencyTest` có **11 lượt kiểm tra đạt** (5 test và 2
concurrency test lặp 3 lần). `P16RestartPersistenceTest` được **skip có chủ đích**
trong suite thường vì chỉ bật bằng môi trường của stack restart.

| Kịch bản | Bằng chứng cần đạt |
| --- | --- |
| Wiring | Flowable dùng cùng JpaTransactionManager và cùng DataSource JPA qua transaction-aware proxy. |
| Ghi JPA + start rồi ném lỗi ứng dụng | SQL JPA đã flush nhưng sau rollback không còn bản ghi, runtime task/instance hoặc history của instance vừa tạo. |
| Cập nhật JPA + complete rồi ném lỗi ứng dụng | Bản ghi trở lại WAITING; cùng task vẫn chờ, biến outcome không được lưu, history chưa kết thúc. Sau đó complete lại thành công và cả hai bên cùng commit. |
| Ghi JPA + claim rồi ném lỗi ứng dụng | Bản ghi không còn; task chưa có assignee và candidate khác vẫn thấy task trong queue; history không giữ assignee vừa rollback. |
| Cập nhật JPA rồi complete với nhánh XOR không hợp lệ | Engine trả INTERNAL_ERROR; bản ghi, task, variables và history vẫn ở trạng thái chờ. |
| Hai candidate claim một task | Một người thắng, người còn lại nhận TASK_CONFLICT hoặc NOT_FOUND; chỉ bản ghi JPA của người thắng tồn tại. Task có đúng owner thắng và chưa kết thúc. |
| Hai yêu cầu cùng assignee complete, outcome trái nhau | Một yêu cầu thắng, một yêu cầu nhận TASK_CONFLICT hoặc NOT_FOUND; chỉ bản ghi JPA thắng tồn tại, có một historic task kết thúc tại đúng end activity của outcome thắng. |

Concurrency dùng hai worker, mỗi worker có transaction REQUIRES_NEW; cả hai
flush bản ghi JPA riêng và đọc cùng task trước khi qua barrier để gọi adapter.
Test xác nhận `pg_backend_pid()` khác nhau, không giả lập bằng hai lời gọi tuần
tự trên cùng connection. Barrier/future/transaction có timeout; lỗi bất ngờ làm
test thất bại, không tự retry để che lỗi. Kết quả chỉ chứng minh các thao tác engine
trên cùng task; chưa thay thế idempotency HTTP hoặc luật nghiệp vụ ở Phase 5.

## 3. Restart — chạy riêng trên volume PostgreSQL test

```powershell
./scripts/Verify-P16Restart.ps1
```

Script tự build image test; không cần chạy Maven trên host. Chỉ chạy một script
restart tại một thời điểm vì project name cố định `bpm-p16-restart`.

1. Dựng PostgreSQL riêng với DB/user `bpm_test`; guard test P1.4 vẫn được áp dụng.
2. JVM prepare deploy/start ba process: direct assignee, candidate queue chưa
   claim và candidate queue đã claim. Lưu mapping deployment/definition/instance/
   task ID trong JPA cùng marker variable. Xác nhận task đã chờ rồi kết thúc JVM.
3. Dừng và recreate container PostgreSQL, giữ volume
   `bpm-p16-restart_restart-data`.
4. Recreate container runner, JVM resume đọc đúng mapping đã lưu bằng run ID;
   kiểm tra business key, IDs, variables, assignee/candidates và history chưa kết
   thúc. Claim queue còn trống, complete cả ba process và xác nhận JPA/history.
5. Dọn deployment/bản ghi đúng run sau khi assertion đạt; thu báo cáo, xác nhận
   ID container DB và runner khác giữa hai lượt, rồi `down` giữ volume.

Riêng lớp restart override JPA thành `update`; `create-drop` của suite thường sẽ
xóa fixture lúc JVM prepare đóng và không phù hợp cho kịch bản persistence.
Không ghép Compose restart với Compose dev hoặc test thường.

Kỳ vọng: script in `P1.6 restart verification passed`; báo cáo ở
`target/p16-restart/<runId>/prepare` và `resume` đều có một test đạt, **không skip**.
Log có ba dòng PREPARED và ba dòng RESUMED; `containers.json` ghi hai cặp ID khác
nhau.

Nếu thất bại, script giữ container/volume để điều tra và dừng, không tự chạy tiếp
hoặc đánh dấu đạt. Báo cáo được thu trước khi thay container test. Sau khi sửa,
chạy lại script tạo run ID mới; dữ liệu của lượt lỗi được giữ để quan sát.

Khi cần dừng stack còn lại sau lỗi (giữ dữ liệu), trong PowerShell:

```powershell
$env:P16_RESTART_STAGE = 'prepare'
$env:P16_RESTART_ID = [guid]::NewGuid().ToString()
docker compose -p bpm-p16-restart -f compose.restart.yaml down
Remove-Item Env:P16_RESTART_STAGE, Env:P16_RESTART_ID
```

Script không xóa volume. Nếu muốn reset **riêng dữ liệu test restart**, chủ động
dùng `down --volumes` thay `down` trong khối trên; không dùng lệnh đó với stack dev.

Kịch bản kiểm chứng restart JVM Spring/Flowable và recreate DB giữ volume;
chưa bao phủ crash đột ngột, backup/restore hoặc failover.
