## 1. Phạm vi

- Tài khoản và hồ sơ người dùng: tạo, cập nhật, khóa, mở, reset mật khẩu tạm, membership và role membership.
- Role/permission: tạo, cập nhật, ACTIVE/INACTIVE và chọn permission từ catalog cố định.
- Tổ chức: cây phòng ban, parent, trưởng phòng, trạng thái và chức danh.
- UI chặn route theo permission hiện tại; backend tiếp tục deny by default cho API trực tiếp.
- Lỗi thiếu quyền và revision conflict được giữ bằng mã HTTP/API ổn định để frontend hiển thị đúng ngữ cảnh.
- Thay đổi quản trị thành công ghi `audit_events` trong cùng transaction nghiệp vụ.

Không thêm endpoint mới trong P2.6. Postman P2.2/P2.3 tiếp tục là contract request hiện hành; không có secret thật được thêm vào repository.

## 2. Audit quản trị

`AuditEventRecorder` là application port. `JpaAuditEventRecorder` lấy actor đã được xác thực, correlation ID hiện tại và ghi sự kiện bằng JPA với propagation `MANDATORY`. Nếu thao tác nghiệp vụ rollback, bản ghi audit thành công cũng rollback.

Các action được ghi:

| Resource | Action |
| --- | --- |
| User | `USER_CREATED`, `USER_UPDATED`, `USER_DEACTIVATED`, `USER_REACTIVATED`, `USER_PASSWORD_RESET` |
| Role | `ROLE_CREATED`, `ROLE_UPDATED` |
| Department | `DEPARTMENT_CREATED`, `DEPARTMENT_UPDATED` |
| Position | `POSITION_CREATED`, `POSITION_UPDATED` |

Mỗi sự kiện có actor, thời điểm tạo, source `ADMIN_API`, entity type/id, correlation ID, result và diff có kiểm soát. Diff không chứa password, password hash, access token, refresh token, session/grant hoặc security version.

## 3. Boundary quyền

| API | Permission |
| --- | --- |
| `/api/v1/admin/users/**` | `identity.users.manage`; update hồ sơ hiện yêu cầu thêm `organization.manage` |
| `/api/v1/admin/roles`, `/permissions` | `identity.roles.manage` |
| `/api/v1/admin/departments`, `/positions` | `organization.manage` |

Frontend chỉ dùng permission để điều hướng và ẩn chức năng không phù hợp. Mọi request vẫn đi qua Spring Security và use case backend. Permission từ client, route hoặc tên role không được dùng làm nguồn cấp quyền.

## 4. Cạnh tranh cập nhật

- User, role, department và position gửi `expectedRevision` khi update.
- Revision cũ trả 409 `REVISION_CONFLICT`; frontend yêu cầu tải lại, không tự retry ghi đè.
- Invariant P2.2 vẫn áp dụng: không chu kỳ, manager ACTIVE thuộc đúng phòng ban, không khóa manager, không vô hiệu hóa phòng ban còn child/member ACTIVE.
- Chỉ sự kiện thành công mới có result `SUCCESS`; request bị 403/409 hoặc transaction rollback không tạo audit thành công.
