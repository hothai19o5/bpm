# P4.1 — Danh mục và dữ liệu cấu hình quy trình

Ngày triển khai: 04/11/2026.

## Phạm vi và dữ liệu

Tái sử dụng hai bảng JPA `business.process_definitions` và `business.process_versions` đã có. Dev dùng `ddl-auto=update`, test dùng `create-drop`; không thêm migration hoặc truy vấn bảng engine để dựng danh mục.

- Definition giữ key duy nhất, tên, mô tả, Owner, trạng thái ACTIVE/INACTIVE và con trỏ phiên bản mặc định `activeProcessVersionId`.
- Version giữ `bpmnXml`, JSONB `stepConfig`/`formBindings` theo element ID, `formVersionId` chung, tác giả/công bố, checksum và mapping engine. Những cột này đã có FK/unique/CHECK trong schema.
- `versionNumber` là version nghiệp vụ trong một definition, `revision` là khóa lạc quan, `engineVersion` là số do engine cấp. Không dùng thay thế nhau hoặc truy vấn latest engine version để chọn cấu hình.
- Tạo mới definition tạo kèm DRAFT v1 trong cùng transaction với audit `PROCESS_CREATED`. XML/form version/mapping engine chưa có, hai JSONB là `{}`, chưa có active version và không deploy Flowable.
- Owner mặc định là actor hiện tại; `ownerUserId` tùy chọn chỉ nhận user ACTIVE. Owner không tự có quyền thiết kế, publish hoặc duyệt task.

P4.1 chỉ tạo draft đầu tiên và đọc cấu hình đã lưu. Chỉnh sửa XML/step config/bindings, validator server, tạo version kế tiếp và publish tiếp tục ở P4.2–P4.8. Không có API nhận XML tùy ý ở bước này. Fixture published trong test chỉ ghi vào DB test để kiểm tra hợp đồng đọc; không phải quy trình đã validate hoặc deploy.

## Hợp đồng API

Tất cả endpoint dùng Bearer JWT hiện có và envelope `ApiResponse`; lỗi trả mã chuẩn của dự án.

| Endpoint | Kết quả | Quyền |
| --- | --- | --- |
| `GET /api/v1/process-definitions` | Danh mục phân trang, chỉ `id/key/name/revision/updatedAt` | `process.catalog.read`, `process.start`, `process.design`, `process.publish` hoặc `process.monitor.all` |
| `POST /api/v1/process-definitions` | Tạo definition + draft v1, trả artifact | `process.design` |
| `GET /api/v1/process-definitions/{definitionId}` | Metadata quản trị gồm Owner/status/active version | `process.design` hoặc `process.publish` |
| `GET /api/v1/process-definitions/{definitionId}/versions` | Lịch sử version phân trang, không chứa XML/JSONB/mapping engine | `process.design` hoặc `process.publish` |
| `GET /api/v1/process-definitions/{definitionId}/versions/{versionId}` | Definition và cấu hình đầy đủ của đúng version thuộc definition | `process.design` hoặc `process.publish` |

Design/publish là quyền quản trị toàn cục theo mô hình một Admin C-06/C-09. `process.monitor.all` chỉ thấy danh mục tối thiểu toàn bộ; quyền monitor/Owner/catalog/start không mở API metadata quản trị. Người chỉ có `process.monitor.owned` không được cấp danh mục toàn cục; policy giám sát hồ sơ theo Owner vẫn thuộc module authorization/runtime.

Danh mục cho catalog/start chỉ gồm definition ACTIVE trỏ tới PUBLISHED version thuộc chính definition đó, có `engineDefinitionId`. MVP cấp các quyền này toàn cục, chưa có ACL khởi tạo riêng từng quy trình. Cùng predicate được dùng trước COUNT và phân trang. Danh mục không thay thế kiểm tra `process.start` khi submit ở P5.2.

Phân trang: `page` mặc định 0, `size` mặc định 20, giới hạn 1–100. Catalog có `sort=key|name|updatedAt,asc|desc`, mặc định `updatedAt,desc`, thêm ID làm thứ tự phụ ổn định. History mặc định `versionNumber,desc`, chỉ nhận `versionNumber,asc|desc`. Offset vượt giới hạn JPA và sort lạ trả 400. Tìm kiếm/lọc và UI quản lý thuộc P4.8.

Body tạo:

```json
{
  "key": "purchase-request",
  "name": "Đề nghị mua sắm",
  "description": "Quy trình mua sắm MVP",
  "ownerUserId": null
}
```

Key khớp `[a-z][a-z0-9_-]{0,99}`, tên không trống và tối đa 200 ký tự, mô tả tối đa 4000. Key trùng trả `409 REVISION_CONFLICT`; cạnh tranh cùng key chỉ tạo một definition/draft/audit. Owner không tồn tại hoặc INACTIVE trả `400 INVALID_REQUEST`. Version không thuộc definition trong URL hoặc ID không tồn tại trả `404 NOT_FOUND`. Thiếu token trả 401, thiếu quyền trả 403 trước khi đọc metadata.

Artifact trả về có cấu trúc `{definition, version}`; `version.metadata` chứa `id/processDefinitionId/versionNumber/status/createdBy/publishedBy/publishedAt/updatedAt/revision`; bên cạnh là `bpmnXml/stepConfig/formBindings/formVersionId/engineDeploymentId/engineDefinitionId/engineVersion/artifactChecksum`.

## Code và Postman

- `process.domain`: model danh mục và policy scope đọc tối thiểu.
- `process.application`: use case tạo/đọc, các DTO và port store/transaction.
- `process.adapter.persistence`: adapter danh mục thật, repository và store JPA; transaction bao trùm lưu dữ liệu và audit.
- `process.api`/`process.config`: bật route/controller và đăng ký các bean đã để khung từ P1.3.
- Postman v3 trong `postman/collections/BPM API/Process Definitions`: 5 request kế thừa auth/biến collection, thêm `processDefinitionId` và `processVersionId`. Request tạo lưu ID từ kết quả thành công để dùng cho request đọc; đổi key khi tạo quy trình khác.
