# P4.5 — Validator server và XML an toàn

Triển khai 05/11/2026. Mục tiêu còn lại của đợt công việc: P4.6–P4.8, kiểm thử và commit riêng từng phase.

## Contract

`POST /api/v1/process-definitions/{definitionId}/validate` nhận `{bpmnXml, stepConfig, formBindings}` của bản đang chỉnh sửa, yêu cầu `process.design` hoặc `process.publish`. Use case xác thực quyền trước đọc definition và kiểm tra process ID đúng key. Thành công trả canonical authoring artifact trong envelope; lỗi `422 VALIDATION_FAILED` có `details[].field/elementId`. Không ghi draft/audit/deploy engine; request không cần đợi có API save P4.6.

## Kiểm tra

Parser namespace-aware và secure processing; tắt DTD, entity, XInclude và tài nguyên ngoài, entity resolver từ chối truy cập. Không trả thông báo gốc parser/SQL. Giới hạn 2 MB, 10.000 XML elements, depth 32, 500 node/flow, ID duy nhất và tọa độ hữu hạn/hợp lệ. Allowlist đóng theo namespace/tag/attribute/vị trí; không nhận listener, Script/Service Task, gateway ngoài XOR, extension lạ, conditionExpression người dùng, processing instruction hoặc expression ẩn trong name/documentation/attribute.

Một executable process đúng key; đúng một start, có end; nguồn/đích flow tồn tại; mọi node tới được từ start và có đường ra end; start/end đúng hướng, không có chu trình tự động khi loại các UserTask wait state. Kiểm tra DI plane, shape, edge, bounds, waypoint và incoming/outgoing references.

XML extension `bpm:configuration` là nguồn metadata; parser JSON bật duplicate-key detection. Projection từ XML/default ref phải khớp tuyệt đối payload bên ngoài. Kiểm tra các key metadata theo loại node; assignment strategy/targets UUID và ACTIVE; một form version chung, definition ACTIVE/version PUBLISHED; quyền trường hợp schema; actions hợp lệ, mỗi action có đúng một flow outcome, không tạo implicit parallel; hạn giờ/ngày lịch; XOR typed field/operator/value, default và nhánh condition. Kiểm tra hiện tại của directory không đóng băng nhân sự tương lai; runtime resolver tiếp tục kiểm tra membership/self-approval khi tạo task ở P5.3.

## Artifact cuối

`ProcessValidationPort.prepareDeployment` chỉ nhận authoring XML đã kiểm tra. Compiler thêm conditionExpression bằng mẫu cố định `${bpmConditions.outcome(execution, 'APPROVE')}` hoặc `${bpmConditions.test(execution, 'BASE64URL_JSON')}`. Không nội suy biểu thức, class hoặc tên bean từ client. Đầu ra được serialize, parse lại an toàn và kiểm tra chính xác tập biểu thức compiler đã tạo trước khi trả. Publish P4.7 sẽ chỉ dùng phương thức này và XML cuối đó.

`BpmConditions` dùng biến runtime `bpmOutcome` và map `bpmFormData`; so sánh số/tiền bằng BigDecimal, ngày bằng LocalDate, boolean đúng kiểu. Token JSON có field/operator/value/type, không chứa code thực thi. Biến task outcome cần reset theo lượt ở P5.6; P4.5 không start/complete instance qua public API.
