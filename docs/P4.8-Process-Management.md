# P4.8 — Danh mục và vòng đời quy trình

Ngày 05/11/2026. Trang `/admin/processes` thay canvas local mặc định bằng danh mục quản trị, tìm tên/mã, tab phiên bản, phân trang và tạo definition + draft. Chi tiết `/admin/processes/{id}` đọc metadata/lịch sử có phân trang, liên kết designer/viewer đúng version, clone, nhân bản, chọn version cho hồ sơ mới và retire. `/processes` dùng danh mục khởi tạo riêng; không suy ra quyền khởi tạo từ design/publish/monitor.

## Hợp đồng API

- `GET /api/v1/process-definitions/management`: design hoặc publish. `q` tối đa 200, tìm literal không dùng wildcard người dùng; `versionStatus` DRAFT/PUBLISHED/RETIRED lọc definition có ít nhất một version phù hợp. Count và paging áp dụng sau filter; mỗi kết quả là một definition, không phải một version. Sort key/name/updatedAt asc/desc, size 1..100.
- `GET /api/v1/process-definitions/startable`: process.start hoặc process.catalog.read, tách riêng quyền quản trị. Chỉ ACTIVE definition trỏ đến PUBLISHED version của chính nó có mapping. Trả id/key/name/versionId/versionNumber, không owner/XML/engine/config metadata. Catalog GET gốc P4.1 giữ hợp đồng minimal cũ.
- `POST /{id}/clone`: process.design; source versionId/expectedRevision, UUID Idempotency-Key. Tạo DRAFT `max(versionNumber)+1` dưới khóa definition, giữ authoring XML/DI/metadata/form binding, không copy deployment/checksum/published fields. Nguồn nháp/công bố/retired đều có thể nhân bản trong tập authoring an toàn; source không bị sửa.
- `POST /{id}/duplicate`: process.design; cùng source/revision/key, thêm key/name mới, tùy chọn description/ownerUserId. Tạo definition độc lập + draft v1. Đổi process ID và DI plane reference bằng DOM an toàn, validate lại; giữ node/flow IDs và metadata. Không deploy hoặc tự chọn version start.
- `POST /{id}/activate`: process.publish; chỉ PUBLISHED có mapping, definition ACTIVE. Chọn default cho hồ sơ mới, có audit; không migrate instance. Có thể chọn lại bản công bố cũ chưa retired.
- `POST /{id}/retire`: process.publish; chỉ PUBLISHED. Đổi thành RETIRED và xóa active pointer nếu đang chọn version đó. Không tự fallback sang bản khác, không suspend/delete engine/deployment/instance/history. Không tái kích hoạt RETIRED; clone thành nháp và publish version mới.

Các mutation có khóa definition, revision và receipt actor/requestKey/fingerprint toàn payload + operation. Retry chính xác trả target cũ và không audit/clone thêm; thay payload/operation với cùng lifecycle key trả 409. Dùng key mới cho một thao tác mới. Receipt và audit cùng transaction; lỗi audit/persistence rollback kết quả. Save non-DRAFT vẫn bị chặn. Với retry sau khi target đã thay đổi, receipt vẫn định danh đúng target; API trả trạng thái hiện tại của target, không tạo một target mới.

Frontend kiểm tra quyền độc lập, xác nhận activate/retire/duplicate; error/conflict có hướng dẫn tải lại, retry mất response giữ khóa của đúng payload. Publisher không thấy tạo/clone/duplicate; designer thiếu publish không thấy activate/retire. Retired được ghi “Ngừng khởi tạo”, kèm giải thích giữ lịch sử và hồ sơ đang chạy. Designer version có liên kết trở về lịch sử. Catalog start chỉ có Tạo hồ sơ khi có cả process.start và record.create; màn runtime được nối ở P5.

## Kiểm chứng

Backend full regression trên PostgreSQL/Flowable test cách ly. Kiểm tra clone/duplicate/retry/revision/permission, search literal/count/paging/status, audit rollback và clone đồng thời. Kịch bản thật deploy v1, start instance v1 đang chờ, publish v2, activate v1, retire v1, kiểm tra start catalog rỗng và instance v1 không bị suspend, complete task v1 rồi đọc history; deployment cũ vẫn tồn tại. Sau đó activate v2. Không dùng start-by-key mới nhất.

Frontend full form/model/Chrome regression, build/lint; Chrome kiểm tra tạo draft qua management, tải lỗi/retry, search/tab/paging, lịch sử, retire/refresh, activate, clone/duplicate retry cùng khóa và catalog start riêng. Có smoke tùy chọn nối Chrome → API thật → Flowable qua `DesignerSmokeServer` test-only, được bảo vệ bằng opt-in và test DB guard. Mẫu mua sắm được tạo bằng modeler/metadata authoring, mở trên canvas, lưu/validate/publish bằng UI, reload viewer và clone; có form binding chung, manager/accounting/director/purchasing/correction, REJECT/REQUEST_CHANGES/RESUBMIT, XOR ngân sách và ngưỡng 50 triệu. Smoke này chứng minh cấu hình/công bố; xử lý runtime theo vai trò và đủ nhánh thuộc P5.

Smoke phát hiện DI `BPMNShape.isMarkerVisible` do bpmn-js xuất cho XOR. Allowlist đã hỗ trợ boolean true/false chỉ trên shape XOR, có regression positive/negative và copy/DI; không mở các extension/attribute ngoài tập MVP.

Kết quả cuối và vị trí log được ghi trong README/Implementation Plan. Restart opt-in không chạy trong full regression không được tính đạt. Không thay migration policy C-17, không đánh dấu UAT/acceptance/runtime P5 đã hoàn thành.

## Chạy smoke API thật

Chỉ dùng PostgreSQL từ `compose.test.yaml`, không chạy đồng thời với suite khác trên cùng DB. Build image tests; khởi động postgres test trước. Từ backend:

```powershell
docker compose -p bpm-p45-test -f compose.test.yaml build tests
New-Item -ItemType Directory -Force target/designer-smoke
docker compose -p bpm-p45-test -f compose.test.yaml run --rm --publish '127.0.0.1:8327:8080' --volume 'D:/Project/bpm-backend/target/designer-smoke:/workspace/target/designer-smoke' -e BPM_DESIGNER_SMOKE=true -e 'CORS_ALLOWED_ORIGINS=http://127.0.0.1:5179' tests sh ./mvnw --batch-mode --no-transfer-progress spring-boot:test-run '-Dspring-boot.run.main-class=com.x.bpm.support.DesignerSmokeServer'
```

Chờ `target/designer-smoke/ready` và server đã lắng nghe. Từ frontend, một terminal khác:

```powershell
$env:BPM_DESIGNER_SMOKE='true'
$env:VITE_API_BASE_URL='http://127.0.0.1:8327'
npx playwright test tests/browser/processPublication.real.spec.ts
```

Kết thúc bằng `Set-Content target/designer-smoke/stop stop` từ backend rồi chờ JVM/container đóng. Fixture chỉ nằm test classpath, tạo tài khoản giả trong bpm_test, tự kết thúc sau 15 phút. Marker cũ được dọn khi khởi động; không có bootstrap production hoặc secret thật. Điều chỉnh đường dẫn bind mount nếu checkout ở nơi khác.
