## Phần P6.1 được đưa lên làm điều kiện cho C08

C08 yêu cầu nhận đủ hàng kèm chứng từ mới hoàn tất. Đã nối tối thiểu task upload/download/link và kiểm tra object; chưa đánh dấu toàn bộ P6.1 hoàn thành. POST `/api/v1/tasks/{id}/attachments` multipart gồm fieldId, expectedRevision và file. Chỉ current assignee có task.complete và đúng ATTACHMENT/EDITABLE field. Khóa record, đọc lại task/revision, kiểm tra tối đa 10 tệp/record và 20 MiB/tệp. Cho PDF/DOCX/XLSX/PNG/JPG (jpeg tương đương); kiểm tra signature/container, chặn path/control characters/macro/traversal/zip quá giới hạn. Không tin MIME client hoặc nhận object key/bucket/actor từ request.

Tạo key UUID dưới prefix record, PUT S3 riêng tư rồi lưu metadata LINKED + field ID/hash/size/uploader và form reference/revision/audit trong transaction. Upload cập nhật record data của đúng field ngay, nên reload khôi phục file và revision. Không đổi engine state/variables cho đến complete. Response mất: retry revision cũ trả conflict, GET task detail lấy kết quả đã commit; không tự upload lại bằng revision mới. Frontend cập nhật expected revision sau upload mà giữ các input chưa lưu khác.

Storage adapter dùng AWS SDK S3 2.57.8 và URL connection client, timeout hữu hạn, default credential provider hoặc credentials ngoài repo; endpoint/bucket/region qua BPM_STORAGE_*. Mặc định tắt để ứng dụng không tự gọi cloud. Bật với một bucket private đã được cấu hình ngoài ứng dụng; endpoint có thể để rỗng để dùng S3 theo region. Không tạo bucket/policy public hoặc presigned URL. `.env.example` chỉ có giá trị rỗng cho credentials.

Trước chấp nhận attachment reference khi complete, kiểm tra metadata thuộc đúng record/field/LINKED và HEAD object còn đúng size/hash metadata. Unknown/cross-record file ID, thiếu object hoặc storage lỗi không thể trở thành chứng từ hợp lệ. GET `/tasks/{id}/attachments/{fileId}` kiểm tra active task scope/field visibility/form reference, GET private object và đối chiếu bytes/hash, trả Content-Disposition attachment/no-store/nosniff. Chưa mở download record sau khi task kết thúc; phần đó nối cùng record access/participant tại P5.8.

S3 write đăng ký compensation trước PUT, nên audit/DB hoặc lỗi sau PUT rollback record/revision/metadata và xóa đúng key mới. Nếu cleanup RPC cũng lỗi thì log key để hỗ trợ; durable orphan cleanup/temp lifecycle/draft upload/unlink và retention/malware vẫn thuộc P6.1/O16, không giả định hai hệ thống có distributed transaction. Không tự xóa file nghiệp vụ đã commit.
